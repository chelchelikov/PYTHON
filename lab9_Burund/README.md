# Лабораторная работа №9. Вариант 5. Учебные задачи

Клиент-серверное приложение на сокетах (TCP + дополнительно UDP).
Сущность **Task**: `id`, `title`, `priority`, `status`, `assignee`.
Специализированная операция: **filter_by_priority**.

## Запуск

```bash
python server.py                 # TCP 127.0.0.1:9090, UDP 127.0.0.1:9091
python client.py                 # можно открыть 3 и более клиентов одновременно
python client.py --timeout 0.5   # клиент с коротким тайм-аутом
python -m unittest discover -s tests -t . -v
```

## Архитектура

```
client.py ──TCP/JSON──► server.py ──► service.py ──► repository.py
                         (RequestHandler)  (TaskService)   (TaskRepository, память)
```

Сетевой код (`server.py`) не изменяет коллекцию напрямую — только через `TaskService`.
Каждый клиент обслуживается в отдельном потоке, сервис защищён `threading.Lock`.

## Протокол

Сообщения — JSON-объекты в UTF-8, граница сообщения — символ `\n` (JSON Lines).

Запрос: `{"command": "...", "data": {...}}`
Ответ: `{"status": "ok", "data": ...}` или `{"status": "error", "error": "..."}`

| Команда | data | Результат |
|---------|------|-----------|
| `list` | — | список задач |
| `get` | `id` | задача |
| `create` | `title`, `assignee`, `priority`?, `status`? | созданная задача |
| `update` | `id` + изменяемые поля | изменённая задача |
| `delete` | `id` | `{"deleted": id}` |
| `filter_by_priority` | `priority`, `min_level`? | задачи приоритета (или не ниже него) |
| `stats` | — | количество задач по статусам и приоритетам |
| `ping` | — | `"pong"` |

Приоритеты: `low`, `medium`, `high`, `critical`. Статусы: `todo`, `in_progress`, `done`.

## Обработка ошибок и тайм-ауты

- сервер недоступен — `ConnectionRefusedError` → «сервер недоступен»;
- разрыв соединения, некорректный JSON, нет поля `command`/`id`, неизвестная команда,
  объект не найден, недопустимые значения — ответ `status: error`, сервер продолжает работу;
- собственные исключения: `ProtocolError`, `TaskNotFoundError`, `ValidationError`;
- тайм-ауты: клиент ждёт ответ 5 с (`--timeout`), сервер отключает клиента после 120 с
  бездействия. Тайм-ауты нужны, чтобы программа не «зависала» навсегда при потере
  связи или зависшем собеседнике. Срабатывание тайм-аута показано в тесте `test_timeout`.

## UDP

Команда `stats` (пункт 8 меню клиента) дополнительно доступна по UDP. Для статистики
допустима потеря пакета: данные справочные, запрос можно просто повторить, а UDP не
требует установки соединения и работает быстрее.
